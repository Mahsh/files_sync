## 1. 背景

### 1.1 业务背景

云手机将画面渲染、音视频编码放在云端完成，通过视频流回传到客户端解码显示。当前推流分辨率相对固定，存在以下问题：

1. **网络波动下体验塌陷**：弱网（4G 信号差、地铁、电梯、Wi-Fi 拥塞）时，固定高分辨率推流会导致带宽不足 → 卡顿、花屏、延迟飙升，用户体感急剧下降。
2. **带宽浪费**：在小屏手机、后台挂机、文字类应用等场景下，仍按高分辨率推流，浪费用户流量和云端编码算力。
3. **高价值场景画质不足**：游戏、视频、设计类应用用户希望获得更高清晰度，但当前无法主动提升。

内部架构文档已明确方向："**根据网络状况与使用场景动态调整画质**"、"根据带宽动态调整图像画质，降低网络传输延迟"。本需求将其落地为可交付的功能。

### 1.2 问题描述

| 角色 | 痛点 |
|------|------|
| 终端用户 | 弱网卡顿；流量消耗高；看游戏画面不够清晰 |
| 运维/运营 | 无法按套餐区分画质档位，缺乏商业化抓手 |
| 研发 | 缺乏统一的分辨率档位定义与切换策略，各端实现不一致 |

### 1.3 目标价值

- **体验**：弱网场景卡顿率下降，网络恢复后画质自动回弹，全程"不卡顿、不断流"。
- **成本**：按需推流，降低无效带宽与云端编码开销。
- **商业**：分辨率档位可作为会员/套餐权益的差异化卖点。

## 2. 范围

### 2.1 功能范围（In Scope）

1. **分辨率档位体系**：定义标准分辨率档位及其对应码率/帧率建议。
2. **手动切换**：客户端提供画质设置入口，用户可主动选择档位。
3. **自动切换（ABR 自适应）**：端云协同引擎根据实时网络质量自动升降分辨率。
4. **切换过程平滑**：切换时保证画面不黑屏、不花屏、不断流，切换耗时可感知但可接受。
5. **策略与限制**：档位上限受套餐/会员权益约束；边缘节点能力约束。
6. **可观测性**：切换事件埋点、码率/分辨率/卡顿指标上报。

### 2.2 不在范围内（Out of Scope）

- 视频编码算法本身的优化（H.264/H.265 编解码内核改造）
- 音频码率自适应策略
- 云端 GPU 渲染性能优化
- 多路并发推流（分屏/多实例同屏）
- 客户端 UI 视觉稿设计（仅定义功能与交互逻辑）

### 2.3 影响范围

| 端 | 影响 |
|----|------|
| 客户端 | 新增画质设置 UI、SDK 支持档位切换与无缝衔接 |
| 端云协同引擎 | 新增 ABR 决策模块、切换信令通道 |
| 云OS / 编码侧 | 编码器需支持运行时改分辨率（重建编码器/重配 SPS/PPS） |
| 管理域 | 套餐-档位映射配置、运营开关 |

## 3. 用户故事

**US-1｜弱网保连续**
> 作为一名通勤用户，我在地铁里玩云游戏，网络时好时坏。**我希望**画面在网络变差时自动降低清晰度而不断流，网络恢复后自动变清晰。**这样**我全程不卡顿、不掉线。

**US-2｜主动选画质**
> 作为一名画质敏感的用户，我在 Wi-Fi 环境下看云手机里的视频。**我希望**能手动把画质调到"高清/超清"。**这样**我能获得更好的视觉体验。

**US-3｜省流量**
> 作为一名流量受限的用户，我在挂机做任务。**我希望**选择"流畅/省流"档。**这样**我不浪费流量，也不影响任务执行。

**US-4｜运营分层**
> 作为运营人员，**我希望**把高分辨率档位绑定到付费套餐。**这样**可以形成会员权益差异化。

## 4. 功能需求

### 4.1 分辨率档位定义

| 编号 | 档位 | 分辨率 | 建议码率 | 建议帧率 | 优先级 | 说明 |
|------|------|--------|---------|---------|--------|------|
| FR-01 | 流畅（省流） | 480P (854×480) | 0.8–1.5 Mbps | 30 fps | P0 | 弱网兜底、挂机、文字类 |
| FR-02 | 标清（SD） | 720P (1280×720) | 1.5–3 Mbps | 30 fps | P0 | 默认档，均衡体验 |
| FR-03 | 高清（HD） | 1080P (1920×1080) | 3–6 Mbps | 30/60 fps | P0 | Wi-Fi/5G 常用 |
| FR-04 | 超清（FHD+） | 1440P (2560×1440) | 6–12 Mbps | 60 fps | P1 | 游戏/视频，付费权益 |
| FR-05 | 自适应（Auto） | 动态 | 动态 | 动态 | P0 | 默认策略模式，由 ABR 决策 |

> 说明：分辨率需与**客户端屏幕宽高比**匹配（16:9 / 19.5:9 / 20:9），非标比例场景按短边对齐、长边按比例裁剪或留边，详见 6.3。

### 4.2 手动切换

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-06 | 客户端提供"画质"设置入口，列出可用档位，标注当前档位 | P0 |
| FR-07 | 选择新档位后 X 秒内完成切换并生效（X ≤ 2s，见 NFR-01） | P0 |
| FR-08 | 手动选择后进入"锁定"状态，N 分钟内不被自动策略覆盖（默认 5 分钟，可配） | P1 |
| FR-09 | 超出套餐权益的档位置灰，点击提示升级引导 | P1 |

### 4.3 自动切换（ABR）

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-10 | 引擎按周期 T（默认 1s）采样网络质量：RTT、丢包率、可用带宽估算、卡顿事件 | P0 |
| FR-11 | 触发降档条件：可用带宽 < 当前档位码率 × 安全系数(1.2) 或 连续卡顿 ≥ 2 次 | P0 |
| FR-12 | 触发升档条件：可用带宽 > 目标档位码率 × 1.5 且 稳定持续 ≥ 3s | P0 |
| FR-13 | 升/降档需**滞回控制**（hysteresis），避免在临界点反复横跳 | P0 |
| FR-14 | 降档响应要"快"（≤ 1 个采样周期），升档要"稳"（防抖动） | P0 |
| FR-15 | 档位变化受套餐上限约束，不自动升到未授权档位 | P0 |

### 4.4 切换平滑性

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-16 | 切换过程不出现黑屏，允许 ≤ 1 帧瞬时轻微模糊 | P0 |
| FR-17 | 切换不导致音频中断，音画保持同步（偏差 ≤ 50ms） | P0 |
| FR-18 | 切换期间不重置会话，不触发重连 | P0 |
| FR-19 | 支持编解码器运行时重配置（SPS/PPS 更新）或编码器热重建 | P0 |

### 4.5 可观测性

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-20 | 上报分辨率切换事件（时间、原档位、新档位、触发原因：手动/自动/降级） | P0 |
| FR-21 | 上报周期性指标：实际分辨率、码率、帧率、RTT、丢包、卡顿次数 | P0 |
| FR-22 | 提供切换成功率、平均切换耗时、弱网自动降档率等运营看板 | P1 |

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|------|------|------|
| NFR-01 | 性能 | 单次分辨率切换耗时 ≤ 2s（P95），切换期间新增卡顿 ≤ 1 次 |
| NFR-02 | 性能 | ABR 决策引入的额外 CPU 开销 ≤ 单实例 1% |
| NFR-03 | 平滑性 | 切换过程黑屏时长 = 0；音画不同步 ≤ 50ms |
| NFR-04 | 稳定性 | 弱网反复波动场景，档位切换抖动次数 ≤ 3 次/分钟 |
| NFR-05 | 兼容性 | 覆盖 480P/720P/1080P/1440P，兼容 16:9、19.5:9、20:9 常见屏幕 |
| NFR-06 | 安全性 | 档位权限校验在云侧完成，客户端不可越权提升 |
| NFR-07 | 合规 | 分辨率与码率符合各应用商店与内容合规要求 |
| NFR-08 | 可配置 | 档位表、滞回参数、采样周期可通过运营配置下发，无需发版 |

## 6. 技术方案建议

### 6.1 整体链路

```
客户端                     网络                  云侧
┌──────────┐                              ┌─────────────────┐
│ 画质设置  │─选档信令──────────────────▶│ 端云协同引擎      │
│ SDK 解码  │◀─视频流（新分辨率）────────│ ABR 决策 + 编码控制│
└──────────┘                              │  ├ 网络质量采样   │
     ▲                                    │  ├ 档位决策       │
     │ 网络质量上报（RTT/丢包/卡顿）          │  └ 编码器重配     │
     └────────────────────────────────────│      (SPS/PPS)  │
                                          └─────────────────┘
```

### 6.2 关键技术点

1. **编码器运行时重配置**：优先走"改分辨率 + 重出 IDR 帧 + 更新 SPS/PPS"，避免整编码器重建带来的延迟；重建作为兜底。
2. **关键帧对齐**：切换必须以 IDR 帧为切点，客户端收到新 SPS/PPS 后立即重初始化解码器。
3. **ABR 决策算法**：基于带宽估算 + 缓冲水位 + 卡顿反馈的混合策略，参考 DASH/HLS 的 ABR 思路，但针对实时交互优化为"降快升慢 + 滞回"。
4. **带宽估算**：结合 RTT、丢包率、发送速率与确认反馈估算可用带宽（类似 GCC/BBR 思路）。
5. **编码芯片**：复用架构文档中的**专用编码芯片 + GPU 直通 + 动态码率编码 + Pipeline 并行**能力，保证高密度下切换开销可控。
6. **信令设计**：档位切换走端云协同独立控制通道，不占用视频流带宽。

### 6.3 分辨率与屏幕适配策略

| 客户端短边 | 可选档位 |
|-----------|---------|
| < 720 | 480P / 720P |
| 720–1080 | 720P / 1080P |
| ≥ 1080 | 720P / 1080P / 1440P |

- 宽高比不一致时：以目标档位短边对齐，长边按**居中裁剪**（保证无黑边）或**等比留边**（保证完整画面），由客户端能力上报后云侧决策。

### 6.4 依赖

- 端云协同引擎（ABR 模块、控制信令）
- 云OS 渲染与编码模块（编码器重配接口）
- 客户端 SDK（档位切换、解码器重初始化）
- 管理域配置平台（档位表、套餐映射、开关）
- 监控埋点平台

## 8. 风险与依赖

| 风险 | 等级 | 影响 | 应对策略 |
|------|------|------|---------|
| 编码器运行时重配在部分硬件/芯片上不支持 | 高 | 切换需整编重建，耗时变长、可能闪断 | 提前在目标芯片矩阵验证；不支持时降级为「重建 + 快速重连」 |
| 弱网下带宽估算不准导致档位抖动 | 中 | 体验反而变差 | 滞回 + 降快升慢 + 稳定期门限 |
| 客户端解码器重初始化耗时 | 中 | 切换有可感知停顿 | 预初始化备用解码器；异步切换 |
| 套餐-档位映射策略频繁变更 | 低 | 配置错误影响用户 | 云侧配置下发 + 灰度 + 回滚机制 |
| 高分辨率下云端编码资源占用 | 中 | 影响单机开数（120 开指标） | 高分辨率档位限流，按节点容量调度 |

**依赖方**：端云协同团队、云OS/音视频团队、客户端团队、运营配置平台、监控平台。

## 9. 附录

### 9.1 术语表

| 术语 | 说明 |
|------|------|
| ABR | Adaptive Bitrate，自适应码率，根据网络与缓冲动态调整码率/分辨率 |
| IDR 帧 | 即时解码刷新帧，编码流中的关键帧，切换后从此帧开始解码 |
| SPS/PPS | H.264/H.265 序列参数集/图像参数集，描述分辨率等编码参数 |
| 滞回（Hysteresis） | 设置不同的升/降门限，避免在临界点反复切换 |
| 端云协同引擎 | 云手机负责端云音视频协同、设备仿真的核心组件 |
