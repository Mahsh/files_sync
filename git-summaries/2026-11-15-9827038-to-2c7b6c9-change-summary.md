## 2. 核心改动摘要

1. **`git-summary` skill 重写核心语义**：从"分析单次 diff"升级为"分析**任意两次提交之间**的 diff"，明确三种对比模式（两次提交之间 / 分支对比 / 工作区改动），并新增"执行准备"章节强制要求确认仓库路径与对比范围，**严禁自行猜测对比基线**。
2. **补充严格的操作规范**：新增 Git 命令速查表（7 条命令）、大仓库输出量控制规则（变更 >30 文件先取 stat、跳过二进制/锁文件、单文件 >500 行只读关键 hunk）、上下文补充可选流程。
3. **影响面分析细化为五层**：协议层/业务层/配置层/基础设施层/文档层，每层给出具体判断依据（如协议层看 protobuf、RPC、字段增删改）。
4. **三份 skill 的归档路径统一迁移**：`prd-generator`、`tech-doc`、`git-summary` 的输出目录从 `memory/knowledge-base/samples/` 改为 `sync_files/`（GitHub 同步目录，PC 与移动端双向可见），并保留目录不存在时的回退逻辑。
5. **明确"不自动上传 Dify 知识库"**：PRD 与技术方案归档时不再自动入库，改由用户在 Dify 控制台手动完成，避免代理/权限问题导致失败。
6. **`.gitignore` 增加关键防御规则**：新增 `sync_files/`（独立 git 仓，防止双重跟踪）、`.trash/`、`_*.py` 忽略项。
7. **总结模板结构升级**：`summary_template.md` 将模糊的"对比基线 {{base}}"拆为明确的"起点 commit / 终点 commit"双字段，表头新增对比范围行。

## 4. 风险提示

| 风险 | 描述 | 建议 |
|------|------|------|
| 归档路径变更导致产物"消失" | 归档目录从 `memory/knowledge-base/samples/` 迁到 `sync_files/`，旧路径的历史产物不会自动迁移，查找时可能"找不到" | 一次性梳理 `samples/` 下存量 PRD/技术方案/总结，评估是否需要搬运到 `sync_files/` 对应子目录 |
| `sync_files/` 被 gitignore 双重跟踪风险 | 注释明确该目录是独立 git 仓的克隆，若有人误在本仓库 add，会形成嵌套仓库混乱 | 已加 ignore 规则防御；建议在 README 或 AGENTS.md 补一句"sync_files 不纳入本仓跟踪" |
| 依赖 `sync_files/` 目录存在 | 归档逻辑依赖 GitHub 同步目录，若同步仓未初始化或克隆失败，产物会走回退路径，造成产物位置不一致 | 增加归档前目录可用性检查，回退时明确日志告警 |
| 对比基线误判 | 新规范要求"严禁自行猜测对比基线"，但用户只说"最近改动"时仍需交互确认，可能打断自动化流程 | 在 skill 中约定：无法确认时默认取 `HEAD~1..HEAD` 并在输出中显式标注假设 |
| 中文编码显示 | diff 中 SKILL.md 中文在部分终端显示为乱码 | 仅影响阅读体验；建议统一文件编码为 UTF-8 无 BOM，并在 Windows 侧设置 `chcp 65001` |
